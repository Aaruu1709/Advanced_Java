Executor Framework:
Executor Framework Java used to manage and run tasks using a pool of threads,
 instead of manually creating and controlling threads one by one.

 Simple Language:

 Instead of doing this every time:

 create thread
 start thread
 manage thread
 destroy thread
 You give your task to the Executor Framework,
  and it handles thread management for you

  Why It Exists

  Manual thread creation causes:

  too many threads
  memory waste
  slower performance
  difficult management

  Executor Framework solves this by using thread pools.
  --------------------------------------------------------
  Before Executor Framework (Old Way) We Used Manual Threads
  That means every time we wanted background work, we created a thread ourselves.

----------------------------------------------------------------------------
Executor Framework in Java is a high-level concurrency utility used to
manage and run multiple tasks asynchronously using a pool of reusable threads,
instead of creating threads manually.

Executor Framework helps execute tasks efficiently by using thread pools and task management.
----------------------------------------------------
Why Reusability Matters

Creating threads repeatedly is expensive because:

Memory allocation
Stack creation
OS scheduling cost
Context switching overhead

So Executor uses a thread pool:

5 threads created once
Reuse same 5 threads for many tasks
That improves performance.
---------------------------------------------
Types of Executor Framework:
1. Fixed Thread Pool
Executors.newFixedThreadPool(5);
Meaning:
Creates 5 reusable threads.
If more tasks come → wait in queue.
Use:
When you need limited concurrent workers.
Example:
API requests, DB tasks.
Restaurant has 5 chefs only.


2. Cached Thread Pool
Executors.newCachedThreadPool();
Creates threads as needed.
Reuses old idle threads.
Can grow large if too many tasks.
-Need more workers? Hire instantly.
-No work? Remove idle workers.


3. Single Thread Executor
Executors.newSingleThreadExecutor();
Meaning:
Only 1 thread executes tasks one by one.
Use:
Sequential processing, ordered tasks.
One cashier serving customers one by one.

4. Scheduled Thread Pool
Executors.newScheduledThreadPool(3);
Workers run tasks at specific time
Meaning:
Runs tasks after delay or periodically.
Where Used:
Send email every day
Cleanup temp files every hour
Poll server every 10 sec
Alarm clock workers.

5. Work Stealing Pool (Advanced)
Executors.newWorkStealingPool();
Smart workers share each other’s work
Meaning:
Uses multiple processors efficiently.
Use:
Parallel CPU-heavy tasks.
If one worker is free, he helps another worker.

| Type                 | Purpose                  |
| -------------------- | ------------------------ |
| FixedThreadPool      | Limited reusable threads |
| CachedThreadPool     | Dynamic threads          |
| SingleThreadExecutor | One thread sequential    |
| ScheduledThreadPool  | Delayed / repeated tasks |
| WorkStealingPool     | CPU parallel work        |


Most Used in Industry
✅ FixedThreadPool
✅ ScheduledThreadPool
✅ SingleThreadExecutor (some cases)

Step 2: Single Thread Executor
Understand:
tasks run one by one

import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

class MyTask implements Runnable {

    private int id;

    public MyTask(int id) {
        this.id = id;
    }

    @Override
    public void run() {

        System.out.println(
            "Task " + id +
            " started by " +
            Thread.currentThread().getName()
        );

        try {
            Thread.sleep(2000);
        } catch (Exception e) {
        }

        System.out.println("Task " + id + " completed");
    }
}

public class Main {

    public static void main(String[] args) {

        ExecutorService executor =
                Executors.newSingleThreadExecutor();

        executor.submit(new MyTask(1));
        executor.submit(new MyTask(2));
        executor.submit(new MyTask(3));

        executor.shutdown();
    }
}

Why Use submit()?
Because executor handles:
✅ thread selection
✅ queueing
✅ scheduling
✅ reuse of threads
✅ async execution

Important Difference
submit()

Used to submit task to pool.

start()

Used when manually creating thread.
